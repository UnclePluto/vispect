# 手机号统一登录与多机构切换设计

- 日期：2026-10-15
- 项目：Vispect
- 状态：会话中的整体方案已确认；本文待用户审阅，尚未开始实施计划或产品代码修改。
- 基础：已交付的多租户健康管理平台；保留 PostgreSQL 强制 RLS、机构内医生权限、配额和审计机制。
- 与原设计的关系：本文替代原设计中的机构标识／用户名登录、账号仅属于一个机构及机构管理员重置登录密码的规则；其余业务规则继续生效。

## 1. 目标与已确认规则

用户用手机号和密码登录，无须输入机构标识。只有一个可进入空间时直接进入；有多个时先选择。管理页面顶部的机构名称改为下拉选择器，用户可以切换自己所属的机构。

已确认：

1. 一个手机号对应一个统一登录身份、一套密码，可以属于多个机构。
2. 同一人在不同机构可以有不同角色，例如 A 机构管理员、B 机构医生；权限按当前机构独立配置。
3. 机构管理员添加已经注册的手机号时，直接建立本机构成员关系，不需要邀请确认，也不改变原密码。
4. 机构管理员只能管理本机构成员，不能重置统一登录密码或修改其他机构的成员关系。
5. 统一密码由本人修改或超级管理员重置；切换机构不能绕过原有数据隔离和医生负责关系。
6. 用户可见的“租户”文案统一改为“机构”。内部 `tenant_id` 和现有数据库表名继续使用，不以改名代替权限迁移。

本次交付集中于登录、成员管理、机构选择与切换、权限衔接和旧账号迁移。继续使用密码认证，不增加短信认证、自助注册或患者登录。

## 2. 方案选择与身份模型

采用“新增统一登录身份，保留现有机构操作身份”的方案。现有 `Account.id` 已被医生、表单发布人、答案录入人和审计等引用，保留这些 ID 可避免改写历史归属。另一种方案是把现有 Account 直接变成全局账号并重建全部成员关联，迁移范围更大，本轮不采用。

| 实体 | 职责与规则 |
| --- | --- |
| `LoginIdentity`（新增） | 全局唯一的规范化手机号、密码哈希、全局启用状态、首次改密标记、修订号；承担登录和密码认证。 |
| `Account`（保留） | 作为机构成员／平台操作身份，新增 `identity_id` 关联统一身份；保留原 ID、机构、角色、医生关联、机构内姓名、启用状态及修订号。 |
| `Doctor`（保留） | 机构内医生档案，继续与该机构的 Account 关联。两个机构中的医生档案是两份记录，不共享患者和研究关系。 |
| `Tenant`（保留） | 对用户称为“机构”；名称用于展示，内部 UUID 用于识别，名称无须全局唯一。 |

一个身份在一个机构最多有一条可登录的成员关系，角色为机构管理员或医生；本轮不新增同机构复合角色。一个身份可以同时拥有多个机构成员关系和一条平台管理操作身份。平台管理身份不会自动产生任何机构成员资格。

机构角色、成员启用状态和机构内显示姓名以 Account 为准；密码与首次改密标记只以 LoginIdentity 为准。旧 Account 的 username/password 不再用于认证，迁移完成的成员密码字段设为不可用，旧用户名仅保留为内部历史兼容字段。

## 3. 手机号与凭据

本轮登录手机号采用中国大陆手机号：接受 11 位号码，以及带 `+86` 或 `0086` 前缀的等价输入；清除首尾空白和号码内的空格、短横线，统一保存为 `+86` 加 11 位号码。11 位号码须匹配 `1[3-9][0-9]{9}`；其他输入返回明确的字段错误。不同写法不能产生多个登录身份。

手机号格式校验不代表短信核验。账号由管理员建立，继续沿用现有不少于 12 位等密码规则、Django 密码哈希、HttpOnly Cookie 和 CSRF 校验。所有登录失败统一提示“手机号或密码不正确”，认证失败前不返回机构、角色或账号是否存在。

首次改密在选择机构之前完成：新身份即使有多个机构，也只改一次密码。密码变更影响全部机构，撤销该身份其他已登录会话；本人修改密码后保留当前登录并刷新会话凭据。平台重置密码后撤销全部旧会话，并要求下次登录改密。

机构成员编辑页面不提供登录手机号换绑或统一密码重置。登录手机号作为身份标识展示，不能被修改医生联系方式的普通接口顺带更改；历史联系方式保留，不作为自动认定登录身份的依据。本轮不提供登录手机号换绑流程。

## 4. 登录、空间选择与页面行为

登录页只保留“手机号”“密码”和登录按钮，移除机构标识、用户名及平台／机构登录单选入口。平台管理员也从同一入口登录。

服务端认证后产生如下状态：

1. 要求首次改密：进入修改密码页，只允许身份、改密、退出等认证操作。
2. 没有可用空间：显示“暂无可用机构或管理权限，请联系管理员”，允许退出；不进入业务页面。
3. 只有一个可用空间：直接激活该空间并进入其工作台。
4. 多个可用空间：显示选择页；机构项展示机构名称和本机构角色，重名机构使用内部机构编号作辅助区分。只在登录成功后提供本人可用项。

“可用空间”是启用机构中的启用成员关系，以及已启用的平台管理操作身份。若用户同时具有平台权限和机构成员资格，选择页增加“平台管理中心”项；平台管理与机构空间的权限分别计算，不叠加。

机构页面顶部使用标准 Ant Design Select，显示当前机构名称及角色。只有一个机构时仍显示选择器，但无其他可切换机构；平台管理中心可作为具有相应权限用户的单独切换项。切换选项来自服务端本人空间列表，不能列出平台管理接口中的所有机构。

切换步骤：有未保存内容时先提示，用户取消则保持原机构和输入；确认后阻止重复操作、取消旧查询、执行切换、清除业务缓存和页面局部编辑状态、更新角色与菜单，最后进入目标空间首页。切换失败显示原因并保持可用的原空间；原空间本身已被撤销时返回空间选择页。

表单设计器已有未保存标记；本次将患者／医生编辑弹窗、研究基本信息／成员／流程、答案草稿及修订等编辑状态接入统一切换提示。切换不自动保存未完成输入。

## 5. 成员与全局账号管理

### 5.1 新增与编辑成员

机构管理员新增医生时填写姓名和手机号。手机号未注册时，要求设置初始密码并创建全局身份和本机构成员／医生档案，首次登录必须改密。手机号已注册时，界面提示“加入本机构，保留原密码”，不显示密码输入，也不返回其他机构名称、身份或密码状态。

创建必须在最终写入时再次判断手机号是否已存在，避免两个机构并发新增同一手机号时创建两个身份或重置已有密码。已在本机构的成员返回明确重复提示；软删除医生使用恢复入口，不能重新建一份规避删除和额度规则。失败的配额检查不能留下半份成员或医生档案。

机构管理员只能新增／管理本机构医生，不能通过提交角色字段提升为机构管理员；机构管理员的配置继续由平台管理入口负责。机构内的新增医生消耗本机构医生额度；同一人在两个机构各有医生档案时分别计入各自额度。单纯的机构管理员不计医生额度。

新机构初始管理员改用手机号创建或关联已有身份；关联已有身份不要求或修改密码。更换管理员到另一手机号时，建立或复用新用户在本机构的管理员 Account，并停用被替换的管理员关系；保留旧 Account 及其原身份绑定，不把旧记录改绑给新人。若目标用户在本机构已是医生，返回明确冲突，不隐式转换角色。平台调整某机构管理员身份，只影响该机构关系，不能把旧管理员在其他机构的关系转给新手机号。

### 5.2 启用、删除与角色调整

机构内“停用成员”只停用该 Account，不停用 LoginIdentity，不影响其他机构。删除、恢复医生继续沿用现有关联保护、软删除、额度及恢复后保持停用的规则。不得因机构移除成员而级联删除全局身份。

本轮不新增任意角色转换流程；保留现有平台配置机构管理员与机构内医生管理的权限边界。以后如需管理员／医生转换，必须显式处理医生档案与额度，不允许简单改角色绕过约束。

### 5.3 平台全局账号管理

平台增加全局账号管理页，按手机号精确查询账号，展示手机号、姓名和全局状态，允许停用／启用全局身份及重置密码。重置和状态变更带修订号并记录审计；不能通过此页获取临床数据。新增机构管理员配置不等于授予平台管理权限，原平台权限保持受控，不开放机构管理员自助提权。

## 6. 数据权限与事务边界

LoginIdentity 属于认证控制面，不包含患者、研究或答案。运行中的控制面账号可以进行认证所需查询，但仍不能直接读取临床表；业务账号不得直接读取全局密码哈希或列举全局身份。既有 Account、医生及临床业务表保留 FORCE RLS。

控制面获取本人空间清单和目标成员信息时，使用受限的成员元数据查询函数，只返回与已认证 LoginIdentity 关联的 Account ID、机构、角色、启用状态及显示名；不授予控制面任意读取全部医生 Account 行的权限。API 的 identity_id 始终取自已验证会话，不能使用客户端传入的其他用户 ID。

新增医生需要在同一业务事务中完成全局身份关联、机构成员、医生档案、配额和审计。为此提供最小的身份建立／复用数据库函数：业务角色只能在合法机构管理员上下文中调用，返回身份 ID 与是否新建，不返回已有密码，也不能覆盖已有身份。函数与成员写入共用同一连接和事务，避免跨 default/control 两条连接误认为可以整体回滚。平台创建机构／管理员也须保持本次操作整体一致。

相关 SECURITY DEFINER 函数固定安全 search_path、限定调用角色、验证操作者和当前机构，撤销 PUBLIC 执行权限，不提供任意 SQL、任意机构查询或全局更新接口。临床表的原有 RLS、复合外键和运行账号非所有者／非超级用户／无 BYPASSRLS 约束保持不变。

每次业务请求同时检查统一身份启用与密码凭据、当前成员身份、成员启用、机构启用、角色及对象授权；机构内部医生仍须同时满足患者负责关系和研究成员资格。Actor 的 account_id 仍为当前机构操作身份 ID，历史答案、发布人及审计不会改成跨机构共享的身份 ID。

停用当前成员时清除当前活动空间并要求重新选择，其他机构仍可进入；全局身份停用或凭据失效则退出整个登录。停用机构不得导致用户失去其他机构的可用成员关系。

## 7. 会话、切换与多标签页

服务端会话保存统一身份 ID、认证哈希、活动 Account ID 和独立的活动空间版本令牌。尚未选择空间时没有业务 Actor，只能调用认证、本人空间列表及空间选择接口。客户端不能只凭修改 tenant_id、路径、请求体或请求头获得空间权限。

专用切换接口接收目标 Account ID 和当前空间令牌，服务端重新检查该身份是否拥有目标启用成员关系。合法切换更新活动空间及令牌；并发切换只接受与当前令牌匹配的操作，过期操作返回 409。客户端请求头中的空间令牌只用于一致性检查，授权机构仍由服务端会话决定。

所有业务查询、写入和下载都携带发起时的空间令牌。旧标签页请求、切换前尚未发出的写入，以及迟到的旧响应不能被当作新机构操作。旧请求返回 `workspace_changed`（409），前端清空原机构数据并重新读取当前空间。不能忽略不匹配令牌，也不能缺省使用当前机构继续执行旧操作。

切换和业务写入使用以稳定会话标识为键的数据库锁作为屏障；默认／控制面连接必须使用同一 PostgreSQL 锁命名空间。切换完成前等待已获准的旧写入结束；切换后等待中的旧写入重新检查令牌并拒绝。已经开始的查询保持原机构事务，前端通过请求代次丢弃迟到结果。

前端使用请求代次取消和缓存清理，并通过 BroadcastChannel 通知同源其他标签页重新加载空间。通知只是界面同步优化，安全性不能依赖通知必达。刷新页面从服务端恢复活动空间；不从 localStorage 或 URL 推断机构权限。切换不需要重新输入密码，退出登录清除整个统一会话。

## 8. API 与前端边界

保留 `/api/auth/csrf/`、`/me/`、`/logout/` 和 `/change-password/`，改为基于统一身份；新增：

- `POST /api/auth/login/`：手机号和密码，返回统一身份、下一步状态、本人空间列表及已激活空间（若可自动进入）。
- `GET /api/auth/workspaces/`：已认证用户的可用空间，机构名、角色及当前项；未选择空间也可调用。
- `POST /api/auth/switch-workspace/`：目标操作身份、当前空间令牌；返回重新鉴权后的当前空间和新令牌。
- 平台全局账号查询、启用／停用与重置密码接口，与现有机构管理员配置接口分别授权。

机构／医生创建、管理员配置接口改用手机号字段；成员状态与全局账号状态采用不同字段／接口，避免停用范围混淆。手机号精确匹配和密码字段严格校验，未知或越权字段继续拒绝。旧 tenant-login／platform-login 入口在切换版本中退役，不能作为旧用户名或旧成员密码的旁路。

业务 API 路径、数据 UUID、修订号和幂等键机制保持；机构端错误文案改为“机构”。401 表示统一登录失效，403 表示角色禁止，404 表示对象不可用，409 用于修订、配额、重复成员及活动空间冲突。空间被撤销的处理与全局登出明确区分。

前端修改认证状态机、登录、首次改密、空间选择页、顶部选择器、菜单、请求与下载封装、缓存及跨标签页同步。已有动态表单与 2026-10-14 新增的独立“＋”选项按钮保持原行为。

## 9. 旧数据迁移与演示账号

采用增量迁移，保留 Account、Doctor、研究、表单、答案、修订、审计和回执的现有 ID。不删除数据库卷，不用清空业务库替代迁移。

1. 新增统一身份表、可空的 Account.identity_id、约束和受限函数；可空用于保留尚未绑定的历史身份，不允许新业务成员缺失绑定。
2. 提供迁移预检及应用命令，通过明确映射指定旧 Account ID、规范化手机号和每个手机号组的主账号。先预检再原子应用，并支持幂等重跑。
3. 不按姓名、旧用户名或未经确认的联系方式自动合并。一个手机号对应多个旧密码时，由映射中的主账号决定沿用哪个密码哈希；不尝试猜测或同步多个密码。若旧身份要求首次改密，则合并后的身份保留该要求。
4. 同一手机号组出现同机构多条身份、映射中显式指定的全局启用值相互矛盾、映射重复或手机号不合法时，预检报具体冲突；整次应用不部分提交，需明确解决后再运行。旧 Account.is_active 是成员状态，逐条保留；同组成员状态不一致本身不是冲突，不据此把某机构的停用扩散到所有机构。
5. 绑定成功后旧 Account 密码设不可用，旧会话失效。未映射的历史 Account 保留业务引用，但不能使用新登录或旧入口登录；预检报告明确列出这些记录，不静默声称全部迁移成功。
6. 更新 seed_demo，使新建环境直接创建手机号身份；已有演示环境使用明确的演示映射升级，不重置已经修改的密码。为纯虚构演示身份分配文档中明确标注的测试手机号，不给真实未知账号虚构号码。

演示数据至少包括：一个同时属于 A、B 的手机号，A 中为管理员、B 中为医生；A、B 的单机构医生；一个平台管理员；第二机构管理员。输出登录说明中的测试手机号、各机构角色和密码来源，不输出真实用户密码。演示初始化和迁移重跑不重复生成成员或占用额度。

## 10. 验收标准

- 登录界面不再出现机构标识或用户名；平台和机构账号都能用手机号、密码登录。
- 同一手机号不同格式归一，不能重复注册；错误密码和未知手机号都不泄露机构清单。
- 单机构自动进入；多机构先选择；首次改密只执行一次；无可用空间时不能访问任何业务。
- 同一账号在 A 为管理员、B 为医生：切换后菜单、患者范围、研究成员权限及导出范围随之改变，平台权限不会混入机构权限。
- 直接请求非所属机构／他人 Account 进行切换被拒绝；RLS 与同机构复合外键仍拒绝跨机构读写。
- 向 B 添加已有手机号不修改密码、不修改 A 成员、不泄露 A 名称；重复添加及并发新增手机号不会产生重复身份／成员。
- 医生创建遇到满额、关联失败或审计失败时，全局身份关联、成员和医生写入一起回滚；其他机构状态不受影响。
- 机构管理员不能修改全局密码、手机号或其他机构身份；本人改密、平台重置和全局停用按定义撤销会话。
- 停用 A 成员／A 机构不影响 B；恢复医生仍保持其成员停用，历史数据与额度一致。
- 顶部选择器展示本人机构；未保存修改可取消切换；成功切换后不残留旧页面、弹窗、查询结果或下载。
- 用两个真实浏览器标签页验证：一个切换到 B 后，另一个旧 A 页面提交／导出被拒绝，绝不能在 B 创建旧 A 的数据；测试等待中的请求及迟到响应。
- 真实 PostgreSQL 验证全局凭据权限、限定函数执行权限、事务回滚和切换屏障；不能只用前端模拟证明隔离。
- 迁移前后 Account、Doctor、答案及审计 ID 保持，密码选择明确，旧会话失效；更换管理员不把历史操作者改绑给新身份；冲突映射不部分提交，重跑无副作用。
- 更新后端、前端和 Playwright 测试，保留现有研究／动态表单／导出回归；生产构建与容器登录可用，README 提供新测试账号和迁移步骤。

## 11. 后续实施与评审重点

书面设计获批后再形成实施计划，依次覆盖数据库／迁移、统一认证、机构上下文与切换、成员与平台账号管理、前端流程及浏览器验收。业务表结构变化以身份绑定为限，不重写已交付的研究与表单子系统。

重点检查：跨连接事务误用、机构管理员重置全局密码、手机号并发首次创建、未映射旧身份旁路、同机构双身份冲突、切换与写入竞态、下载和跨标签页缓存、成员停用导致误退出所有机构、以及历史审计归属变化。

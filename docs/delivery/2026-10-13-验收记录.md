- Ruling: 原生工作区创建成功但沙箱拒绝写入；已归档空工作区，在可写当前目录的 feature/health-platform 分支实施 — 遵循工作区技能的沙箱降级原则 — 风险：并行操作当前目录时需要避免改动此分支。
- Ruling: 任务标题添加 Task 标记以兼容技能提取器，保留中文标题与任务内容 — 不改变需求 — 风险：无产品行为影响。
- Task 3: Ruling: 配额写入接口新增可选 delta（创建/恢复 1，删除 -1，普通编辑 0）— 防止资源已满时连删除都被创建额度检查拦住；数据库触发器仍负责最终计数与上限 — 风险：调用者必须传入操作方向，触发器会兜底校验实际变化。
- Task 4: Ruling: 为研究成员与患者负责关系选择提供同租户医生 id/姓名选项，其他医生专业档案仍仅管理员可读 — 完整配置流程需要最小人员目录 — 风险：若机构还需隐藏同事姓名，需要新增目录权限。
- Task 4: Ruling: 删除医生后恢复档案保持账号停用，管理员可再明确启用 — 恢复档案与恢复登录权限分别操作 — 风险：恢复后需要额外执行启用。
- Task 5: Ruling: 患者状态使用在管/非在管，仅作档案管理标签，不自动停止研究随访 — 需求要求状态筛选但未指定枚举 — 风险：如需与随访联动需另增业务规则。
- Task 10: Ruling: 患者删除保护限定筛选中、待入组、随访中，不拦截已完成随访 — 计划“未停止”措辞过宽，按设计规范的进行中随访执行 — 风险：如要求历史完成记录也阻止删除，需额外归档策略。
- Task 10: Ruling: 职责转交允许机构管理员或当前负责随访医生操作，新医生必须同时具备患者和研究权限 — 规范未细分转交操作者，采用现有责任人权限 — 风险：如机构要求统一审批，需要增加审批角色。
- Task 11: Ruling: 表单暂停阻止答案草稿、提交、修订；已提交的必需表单仍允许确认访视完成 — 设计只将暂停限定于答案写入，完成操作不修改答案 — 风险：如机构希望连流程推进也暂停，需扩展暂停策略。
- Task 12: Ruling: 导出包含当前草稿与提交答案，并添加答案状态列 — 设计要求导出当前答案，状态防止草稿被误当作已提交 — 风险：如只需提交答案，可新增状态筛选。
- Task 12: Ruling: Excel 单元格超过 32767 UTF-16 单位时拆分为相邻续列，XML 不支持字符显示为 Unicode 转义 — openpyxl 源码确认会静默截断长字符串，必须保留完整信息 — 风险：使用者需要合并续列或解读转义。
- Task 14: Ruling: 恢复测试沿用已实现的 Enrollment.state 与 Study.state，不采用计划样例的 status — 任务 9/10 接口和设计统一定义 state，此处为示例命名笔误 — 风险：无产品行为变化。

- Final: Ruling: 表单暂停后仍允许完成已有必需提交的访视 — 完成不会新增答案 — 风险：若要停止推进须另增规则。
- Final: Ruling: 恢复医生档案不恢复登录 — 分开管理两种状态 — 风险：需额外启用。
